# Project Reflection

## Design Decision: Memory Integration Strategy
For this project, I integrated long-term memory across sessions using a custom `MemoryHook` built upon the `HookProvider` interface instead of manually retrieving history within the main invocation flow or inside individual tools. By using hooks (`MessageAddedEvent` and `AfterInvocationEvent`), the core logic of context retrieval and storage is completely decoupled from the main agent lifecycle. This design decision simplifies the agent's system prompt and core handler. The `retrieve_customer_context` method injects relevant memories transparently right before the agent processes a message, while `save_support_interaction` seamlessly archives the completed turn afterward.

## Challenge Encountered: Tool Result Interference
A key challenge during the memory hook implementation was distinguishing between plain-text customer messages and internal tool results. Because `MessageAddedEvent` captures all user-role messages (including those populated by tool responses), the hook initially risked storing tool outputs—like large blocks of JSON or knowledge base extracts—into the memory, leading to prompt bloat and irrelevant context recall. To resolve this, I added specific guard clauses in the `retrieve_customer_context` and `save_support_interaction` methods that inspect the message `content` list. If the message blocks contained a `tool_result` type, the hook intentionally skips processing them, ensuring only the genuine human-generated messages and final assistant answers are stored in the cross-session memory.

## Production Consideration: Scalability & Cost Management
In a production deployment, managing token costs and latency becomes critical, especially as customer histories grow over time. The agent handles cross-session continuity via long-term vector-based memory rather than injecting the entire historical conversation into the prompt window. By restricting `top_k=5` when querying the `memory_client.retrieve_memories()` function, the context window remains small and relevant. However, for extremely high-volume scenarios, the Lambda-backed tools (e.g., order tracking or refunds) accessed via the AgentCore Gateway MCP could become a bottleneck. To optimize scalability, production environments would benefit from adding request caching (e.g., using ElastiCache for frequent catalog or policy queries) and implementing strict rate limiting at the API Gateway level to prevent excessive invocation costs and ensure smooth concurrency scaling.
